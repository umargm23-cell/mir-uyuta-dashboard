# Мир Уюта — серверный помощник официальных источников

## Что сделано

Функция `official-source` в `supabase/functions/official-source/index.ts` читает **только общедоступные HTML-страницы** разрешённых сайтов производителей. Ответ передаётся существующему помощнику, который предлагает значения для ручного выбора. Подтверждение характеристик остаётся ручным. Никаких секретов Ozon, Wildberries или Supabase в браузер не добавляется.

Проверки: вход через Supabase Auth (`auth: 'user'`), HTTPS, запрет IP и локальных адресов, список разрешённых доменов, проверка всех перенаправлений, общий таймаут, лимит 256 КБ, предварительный небольшой лимит запросов на одно окружение. Последний **не является распределённым лимитом**; перед масштабированием необходимо включить платформенный rate limiting. Сайт производителя вправе запретить автоматический доступ — CAPTCHA и запреты не обходим.

## Одноразовая настройка владельцем в Supabase

1. В Supabase → **Edge Functions** создай и разверни функцию с именем `official-source` из `supabase/functions/official-source/index.ts`. Или используй CLI:

   ```bash
   supabase login
   supabase functions deploy official-source --project-ref npecgcxncwmgbqgqregh --use-api
   ```

2. В Supabase → **Edge Functions → Secrets** добавь `OFFICIAL_SOURCE_HOSTS`: список **проверенных официальных доменов** производителей через запятую, например `nachtmann.com`. Добавляй новые домены после проверки, что ими управляет именно производитель. Не используй `*` или произвольные хосты.

3. **Verify JWT** оставь включённым. Функция принимает только JWT пользователя из текущей сессии; `supabase.functions.invoke` передаёт его автоматически. `supabase/config.toml` задаёт `verify_jwt = true`.

4. В `mir-uyuta-dashboard/v2.html` открой карточку товара, вставь HTTPS-ссылку на сайт производителя, нажми **«Через сервер»**. Если функция ещё не развёрнута или домен не в списке, увидишь понятную ошибку и сможешь использовать ручное копирование характеристик.

После однократной настройки можно добавить секрет `SUPABASE_ACCESS_TOKEN` в **GitHub → Settings → Secrets and variables → Actions → New repository secret** для автоматического деплоя Edge Function при следующих изменениях кода в `main`. Токен вводится только в GitHub Secret, не в чат и не в HTML. Workflow в `.github/workflows/deploy-official-source.yml` пропускает развёртывание, если токен не настроен.

### Безопасность

- Списки доменов и доступы к источникам контролирует владелец.
- Функция не поддерживает логины, cookies, обход платного доступа или капчи.
- Если сайт запрещает получение HTML, вручную перенеси данные из официального источника.
- Не меняй `auth: 'user'` на `'none'`, иначе функция может стать открытым прокси.
- Первая версия сайта и данные в таблицах Supabase сохраняются без изменений.
